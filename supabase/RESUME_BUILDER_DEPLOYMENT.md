# Resume Builder: finish secure deployment

The SQL table `public.resume_builder_resumes` has been created. The application code now routes Resume Builder Save, History, Open/Restore and Delete through the Next.js server API. Resume PDFs are still generated by the browser on demand; PDFs are not stored in Supabase.

## Required Vercel environment variables

In Vercel → project `akshayapkp` → Settings → Environment Variables, add these values for Production (and Preview if you test previews):

- `SUPABASE_SERVICE_ROLE_KEY`: the **service_role/secret** key from the same Supabase project as `NEXT_PUBLIC_SUPABASE_URL`. Never use a `NEXT_PUBLIC_` prefix for this key. Never commit or share it in chat.
- `RESUME_SESSION_SECRET`: a random secret of at least 32 characters. Generate one locally, for example with Node.js: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`.
- `ADMIN_LOGIN_USERNAME`: choose the administrator login username.
- `ADMIN_LOGIN_PASSWORD`: choose a strong administrator password. Do not use the old demo password `admin`.

Confirm `NEXT_PUBLIC_SUPABASE_URL` points to project ref `suuobvhlfgjyjevjoecx`. Keep `NEXT_PUBLIC_SUPABASE_ANON_KEY` as the browser key already configured. Do not paste any secret values into GitHub or a chat.

After adding environment variables, redeploy the Vercel project so the server routes receive them.

## Staff login compatibility

The server login route verifies staff against the existing Supabase `staff` table and accepts either the stored plain password or its SHA-256 hash to preserve compatibility with the current table. Prefer migrating staff passwords to a proper password hash and Supabase Auth before broader security hardening. The service-role key is used only server-side.

## Current behavior and limits

- The server issues an HttpOnly, signed, eight-hour session cookie.
- Staff users can access only records whose `created_by` matches their verified session name. Admin can view all records.
- The table has RLS enabled and intentionally has no anon/public policies.
- Resume form data is stored as JSONB, including any photo data URI included by the form. Very large photos may exceed the API's 1.5 MB request limit; crop/resize photos before saving.
- Existing records in browser localStorage key `resume-builder-resumes-v1` are not deleted or automatically migrated. They remain in that browser; export/import migration is a separate task.
- This repository change has not been verified with a production build or a live save test. After env configuration and redeploy, test admin login, save a sample resume, reload, open it from History, update it, delete the sample, and print/download PDF before using real personal data.
